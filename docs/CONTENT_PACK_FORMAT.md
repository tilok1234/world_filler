# Worldfiller content pack — format 1 (FROZEN)

Status: **Frozen at pack format 1** (freeze review resolved 2026-07-28;
see `docs/FREEZE_REVIEW_FINDINGS.md`). File names, field names, and id
schemes never change shape within format 1; later format versions may
append fields but never repurpose them. This document plus the reference
verifiers (`src/consume/verifyPack.ts`,
`consumers/godot-proof/verify_content_pack.gd`) are sufficient to build a
game-side importer without reading any other worldfiller source. The two
reference verifiers implement every numbered obligation below and accept
and refuse the same packs; where a malformed pack is involved, refusal is
the specified behavior for both.

## What a content pack is

The deterministic gameplay-structure layer for exactly one WorldForge world:
where bosses live, which anchors are dungeons, which ground belongs to which
spawn territory, how danger progresses. It is generated by
`wf-fill export <world-pack> <recipe> [out] [--strict]`, which refuses to
write anything unless the nine-gate audit passed. The pack never modifies
the world and never changes walkability — every claim it makes is verifiable
against the world pack alone.

Export refusal semantics: a recipe whose `base.generationIdentitySha256`
pin does not match the world pack refuses at export in **every** mode,
exactly like `plan`/`place`/`territories` (`validate` deliberately still
runs on a stale pin — its G7 gate is the diagnosis). Invalid locks are
dropped with a per-lock diagnosis in `lockReport` and a G6 warning by
default; under `--strict` they are failing gates and the export refuses.

Write semantics: the exporter stages the complete pack in a sibling
temporary directory and renames it over the destination, `manifest.json`
written last. A directory without a readable `manifest.json` is not a
content pack; re-export replaces the destination directory's previous
contents entirely.

## Layout

```text
<name>-content/
  manifest.json        identity + hashes; never listed in its own files table
  content-plan.json    per-region danger bands and budgets (plan format 1)
  placements.json      bosses + dungeon bindings (placements format 1)
  territories.json     spawn territories (territories format 1)
  report.json          the audit that authorized this export (report format 1)
  renders/             OPTIONAL inspection PNGs — never hashed, never payload
```

All payload files **and `manifest.json` itself** are canonical JSON: keys
sorted (UTF-16 code-unit order), two-space indent, LF, one trailing
newline, UTF-8, safe integers only. Entire packs are byte-stable —
identical inputs reproduce identical bytes, manifest included. No
timestamps exist anywhere; identity is hashes.

## manifest.json

```jsonc
{
  "pack": "worldfiller-content-pack",
  "packFormat": 1,
  "world": "fen-hollow",                       // world pack directory name at export time
  "adapter": { "name": "worldfiller", "version": "0.1.0" },
  "directorBehaviorVersion": 6,
  "rulePacks": { "analysis": 1, "plan": 1, "placement": 3, "territory": 3, "validate": 2, "export": 2 },
  "analysisVersion": 1,
  "recipeName": "basic-direction",
  "directorSeed": 103991,
  "directorRecipeSha256": "<64 hex>",
  "base": {
    "generationIdentitySha256": "<64 hex>",    // world identity this pack was directed against
    "artifactFormat": 8,
    "artifactSha256": "<64 hex>",              // sha256 of the world pack's world.json bytes
    "width": 64,
    "height": 64
  },
  "counts": { "placements": 2, "territories": 13, "placementFailures": 0, "territoryFailures": 0, "unboundAnchors": 3 },
  "files": {                                   // sha256 of each payload file's bytes
    "content-plan.json": "<64 hex>",
    "placements.json": "<64 hex>",
    "report.json": "<64 hex>"
    // "territories.json": "<64 hex>"          (all four entries, see below)
  }
}
```

`files` MUST contain exactly the four entries `content-plan.json`,
`placements.json`, `report.json`, `territories.json` in format 1 — no
fewer (an unlisted payload would be consumed unhashed), no more (an
unknown name is an error under obligation 5). Keys are bare file names,
never paths. Later pack formats may append names; a format-1 importer
refuses anything but these four.

`manifest.json` is the only file in the pack no hash covers. Every
identity field and count it carries duplicates a value inside the hashed
payload documents, and an importer MUST cross-check them (obligation 6);
`counts` mirrors the payload array lengths and may be trusted only after
that check.

## Importer obligations (the blessed checks)

An importer MUST, in order:

1. Require `pack == "worldfiller-content-pack"` and `packFormat == 1`;
   refuse anything else (no best-effort reads of unknown formats).
   `packFormat` comparison is exact — `"1"` or `1.9` is not format 1.
   Within packFormat 1 every payload format field is likewise 1:
   `planFormat`, `placementsFormat`, `territoriesFormat`, `reportFormat`
   MUST each equal 1, refused otherwise.
2. Require `files` to list exactly the four payload names, hash-verify
   every entry against the payload bytes, and parse the payloads from
   the same bytes that were verified.
3. Cross-check the base pairing against the world pack it is loading
   beside: `base.generationIdentitySha256 ==
   worldManifest.generator.generationIdentitySha256` AND
   `base.artifactSha256 == worldManifest.baseArtifactSha256`, and
   require `base.artifactFormat` and `base.width`/`base.height` to agree
   with the world pack. A mismatched pair refuses at import, not at play
   time.
4. Require `report.json` `.ok == true` (the pack was audited; a hand-built
   pack without a passing report is not a valid pack).
5. Treat unknown ids and enum values in the **closed vocabularies** as
   errors, never as defaults. The closed, format-frozen vocabularies are:
   - `placements[].rule` ∈ `world_boss.v1 | dungeon_binding.v1`
   - `territories[].cells.encoding` ∈ `runs`
   - `territories[].respawnPressure` ∈ `low | medium | high`
   - `report.gates[].status` ∈ `pass | warn | fail`
   - `lockReport[].status` ∈ `held | invalid`
   All other string vocabularies are **open** and behavior-versioned —
   they legitimately gain values under a `directorBehaviorVersion` or
   rule-pack bump while `packFormat` stays 1, and importers MUST NOT
   refuse unrecognized values in them: `candidateFunnel[].stage`,
   `scoreTerms[].term`, `failures[].reason`, `unboundAnchors[].reason`,
   `lockReport[].reasons[]`, plan waiver strings, gate ids/names,
   `channel` paths, `anchorPoiType`, and `enemyId` (game-owned).
6. Cross-check the manifest against the hashed payloads: the manifest's
   `directorRecipeSha256`, `directorBehaviorVersion`, `recipeName`,
   `directorSeed`, and `base.generationIdentitySha256` equal the copies
   embedded in each payload document, and `counts` equal the actual
   array lengths.

Walkability truth is the world pack's `walkability.json` bitgrid
(`base64-bitpacked-row-major-lsb-first`, bit i = y*width+x, walkable = 1).
The reference verifiers re-check every placement and territory cell against
it; an importer may repeat that spot-check cheaply at load.

## Placement and territory ids

Ids are opaque unique keys. The only structure format 1 guarantees is the
prefix — `placement.world_boss.` or `placement.dungeon.` (matching the
row's `rule`), `territory.` — and a trailing `.<decimal slot>`. The middle
segment is the `regionId`, but region ids themselves contain dots
(informative scheme: `region.<biome-short>.<anchorIndex>`, where
`<biome-short>` derives from the upstream material vocabulary), so ids
MUST NOT be parsed to recover it: read `regionId` from the explicit
field. Recipe locks can only carry ids that match this scheme and agree
with the lock's own `rule` and `regionId` (enforced at recipe
normalization), so locked rows never violate it. Game-side runtime
deltas should be keyed by the whole id string.

## placements.json (format 1)

Top level: `placementsFormat`, version identity (`directorBehaviorVersion`,
`rulePacks`, `analysisVersion`, `recipeName`, `directorSeed`,
`directorRecipeSha256`), `base` (`generationIdentitySha256`,
`artifactFormat`, `width`, `height`), `placements[]`, `failures[]`,
`unboundAnchors[]`, `lockReport[]`.

Each placement:

```jsonc
{
  "id": "placement.world_boss.region.mud.1245.0",  // or placement.dungeon.<regionId>.<slot>
  "rule": "world_boss.v1" | "dungeon_binding.v1",
  "regionId": "region.mud.1245",
  "cell": [31, 59],                 // boss: arena center; dungeon: anchor poi cell
  "accessCell": [31, 59],           // walk-up ground, always walkable+reachable
  "anchorPoiId": 3 | null,          // dungeon: the world pack poi id it binds
  "anchorPoiType": "poi.cave" | null,
  "inSafeZone": false,              // accessCell inside a settlement safe zone (any rule;
                                    // bosses are false by construction in format 1 — arenas
                                    // refuse safe-zone cells and the boss access cell is in the arena)
  "arenaOrigin": [28, 56] | null,   // boss: top-left of the reserved arena square
  "arenaSide": 6 | null,
  "exclusionRadius": 16,            // spacing buffer radius around cell
  "locked": false,                  // true when held by a recipe lock
  "channel": "world/region.mud.1245/reroll.0/boss/0" | "locked",
  "draw": 3,
  "score": 1104,
  "scoreTerms": [ { "term": "clearance", "value": 875, "weightPermille": 400, "contribution": 350 } ],
  "candidateFunnel": [ { "stage": "reachable", "remaining": 212 } ],
  "topCandidates": [ { "cell": [31, 59], "score": 1104 } ]
}
```

`scoreTerms`, `candidateFunnel`, and `topCandidates` are **explanation
data**: their entry shapes are frozen exactly as shown, but their
contents (term/stage vocabularies, list lengths, values) are
behavior-versioned diagnostics. Importers MUST NOT drive gameplay from
them; read them for tooling and debugging only.

Locked placements (`"locked": true`) carry sentinel explanation values:
`channel` is the literal string `"locked"`, `draw` and `score` are `0`,
`scoreTerms` and `topCandidates` are empty, and `candidateFunnel` is
exactly `[{ "stage": "locked", "remaining": 1 }]`. These are
placeholders, not measurements; importers must not interpret them.

`failures[]` entries (placement solving that could not complete):
`{ regionId, rule, slot, candidateFunnel[], message }`. `unboundAnchors[]`
entries (anchor POIs that did not become dungeons):
`{ poiId, poiType, cell, regionId | null, reason }` with `reason` in the
open vocabulary (currently `not_selected_budget`, `unreachable_anchor`,
`spacing_blocked`, `no_region`, `region_zero_budget`, `no_content_zone`).
`lockReport[]` entries: `{ id, status: "held" | "invalid", reasons[] }`
with `reasons` in the open lock-invalidity vocabulary (currently
`region_missing`, `over_budget`, `cell_not_walkable`, `cell_unreachable`,
`arena_blocked`, `anchor_missing`, `anchor_changed`,
`in_no_content_zone`). `failures[].message` strings are diagnostics, not
contract.

Runtime split: the pack carries permanent structure. Spawning the boss,
door state, kill state, and loot are game runtime concerns; persist them as
game-side deltas over the deterministic base (upstream doctrine), keyed by
placement `id`.

## territories.json (format 1)

Top level: `territoriesFormat`, version identity, `base` (same shapes as
placements.json), `territories[]`, `failures[]`, `coverage`.

Each territory:

```jsonc
{
  "id": "territory.region.mud.1245.0",
  "regionId": "region.mud.1245",
  "dangerBand": 2,                          // 0 = safe heartland band
  "seedCell": [18, 44],
  "cells": { "encoding": "runs", "runs": [[16, 42, 5], ...] },  // [x, y, length], never crossing rows
  "cellCount": 65,
  "roster": [ { "enemyId": "enemy.mire_creeper", "weightPercent": 35, "nightOnly": false } ],
  "packSize": [2, 6],
  "maxActive": 5,
  "respawnPressure": "low" | "medium" | "high",
  "elitePermille": 30,
  "channel": "world/region.mud.1245/reroll.0/territory/0",
  "draw": 1
}
```

The run rule is normative for readers as well as writers: an importer
MUST refuse a run whose `x < 0`, `y < 0`, `length < 1`,
`x + length > width`, or `y >= height` — runs never wrap into the next
row, and a violating run is a malformed pack, not data. `cellCount`
equals the number of distinct cells the runs decode to.

`failures[]` entries: `{ regionId, slot, reason, message }` with `reason`
in the open vocabulary (currently `insufficient_hostile_ground`,
`fragmented_hostile_ground`, `no_matching_roster`).

`coverage` is `{ regions: [], totalHostileWalkable, totalCovered }` with
one `regions[]` row per plan region — zero-budget regions included, with
`budget: 0, covered: 0, emitted: 0` — so the totals are world totals over
every planned region. Each row:
`{ regionId, hostileWalkable, covered, coveragePermille, budget, emitted }`.

`enemyId` values come from the DirectorRecipe's content library — game-owned
vocabulary. The runtime interprets roster weights, pack sizes, `maxActive`,
respawn pressure, and elite chance; the pack only fixes the ground and the
budgets. Territory cells never overlap each other, safe zones, or any
placement's exclusion radius.

## content-plan.json and report.json

`content-plan.json` (plan format 1) is the per-region brief: top level is
`planFormat`, version identity, `base`, `spawnRegionId`, `regions[]`,
`worldBudget` (`{ worldBosses: { target, allocated }, territories,
encounterSites, dungeonBindings }`), `unassignedDungeonAnchors`, and
`checks` (`{ progressionWarnings: [{ regionId, dangerBand, chokeBand }],
worldWaivers: [] }`). Each `regions[]` entry: `{ id, biome, cellCount,
walkableCells, hostileWalkableCells, reachableCells, safeSharePermille,
medianSpawnDistance | null, dangerBand | null, dangerOverridden,
regionClass: "minor" | "standard" | "major", budgets: { territories,
encounterSites, dungeonBindings, worldBosses }, dungeonAnchorCandidates,
waivers[] }` — useful for debug overlays and quest/level tuning.

`report.json` (report format 1) is the audit that authorized the export:
top level is `reportFormat`, version identity (no `directorSeed`), `base`
(`generationIdentitySha256`, `artifactFormat` only), `strict`, `gates[]`
(`{ id, name, status: "pass" | "warn" | "fail", details[] }`), `ok`.
Gate ids/names and detail strings are open diagnostic vocabulary.

Neither is required at runtime, but both are hashed payload so tooling can
trust them.

## Versioning

`packFormat` gates structural shape. `directorBehaviorVersion` and
`rulePacks` identify generation semantics: the same recipe and world under
a different behavior version may place content differently — treat packs as
replaceable derivatives, pinned by `directorRecipeSha256` +
`base.generationIdentitySha256`. When the base world regenerates under a
new upstream behavior, re-direct and re-export; locks carry survivable
intent across that boundary (invalid ones are named in `lockReport`).
